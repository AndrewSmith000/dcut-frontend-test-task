## 1. Дженерики
Дженерик - механизм, позволяющий функциям обрабатывать данные, тип которых определяется при использовании функции. Отличие от any в том, что any не позволяет в дальнейшем контролировать тип входящего значения, дженерик же запоминает тип и позволяет использовать его в дальнейшем. Дженерики можно ограничивать для большего контроля над входящим значением, например

```
function processSomeData<T extends { id: string }>(data: T): T {
  return data
} 
```

явно указывает TypeScript, что аргумент data может иметь любой тип, но в нём обязано присутствовать поле id с типом string, а также гарантирует сохранение конкретного типа T с наличием id в возвращаемом значении.
## 2. type vs interface
И type, и interface позволяют описывать типы, однако у каждого механизма свои преимущества:

- type удобен за счёт возможности использовать union (описывает значение, способное принимать один из типов, как конструкция "или") и tuple (описывает тип как массив фиксированной длины с элементами конкретных типов):

```
type Id = string | number
```

```
type Coords = [number, number]
```

- interface имеет более удобные механизмы расширения: extends (построение интерфейса на базе существующего) и множественное объявление (declaration merging), в результате которого члены интерфейса будут объединены

```
interface Human {
  age: number
}

interface Employee extends Human {
  position: string
}
```

```
interface Human {
  age: number
}
interface Human {
  name: string
}
```

- type также имеет механизм, схожий по результату с extends - intersection

```
type User = {
  id: string
}

type Admin = User & {
  permissions: string[]
}
```

Оба механизма частично взаимозаменяемы при описании объектных типов, но, ввиду их различий, среди большинства разработчиков ради удобства действует соглашение - использовать интерфейсы для описания контрактов объектов, а type в случаях, когда требуется union/tuple

## 3. Intersection и Union
Union - механизм, позволяющий описать, что тип может принимать значение любого из переданных типов. Intersection - конструкция, обязующая тип использовать все элементы переданных типов. Например,

```
type State = "pending" | "done" | "error"
```

говорит о том, что State может принимать одно из трёх значений.
Результат Intersection -тип, который одновременно удовлетворяет требованиям всех составляющих типов. Например, в результате следующего объявления тип Pet обязан будет иметь такие свойства, как age, species и owner:

```
type Animal = {
  species: string
  age: number
}
type Pet = Animal & {
  owner: string
}
```

type guard - механизм, позволяющий TypeScript сузить тип в определённой ветке кода на основании проверки. Например:

```
type Id = string | number

function printId(id: Id): string {
  if (typeof id === "string") {
    return id.toUpperCase();
  } 
  return id.toString()
}
```

Или с объектными типами:

```
type Fish = { swim: () => void };
type Bird = { fly: () => void };

function isFish(pet: Fish | Bird): pet is Fish {
  return "swim" in pet
}

function move(pet: Fish | Bird) {
  if (isFish(pet)) {
    pet.swim();
  } else {
    pet.fly();
  }
}
```

Важно, что проверка происходит при выполнении кода, а TypeScript на этапе компиляции анализирует её и сужает тип в соответствующей ветке кода.

## 4. KeysOfType
В данном примере KeysOfType - переиспользуемый дженерик, делающий следующее:

- keyof T - собирает union из всех ключей типа T
- K in keyof T - проходит по каждому ключу в получившемся union
- T[K] - обращается к типу каждого ключа K
- T[K] extends U - проверяет каждый конкретный тип на совместимость с типом U
- T[K] extends U ? K : never - если тип конкретного ключа совместим с типом U, то оставляет сам ключ K, иначе заменяет его на never
- [keyof T] в конце извлекает значения всех свойств полученного типа, а поскольку неподходящие значения — never, в итоговом union они исчезают, т.е остаются ключи свойств, тип которых совместим с U

## 5. Utility types
- Partial: на основе переданного типа создаёт новый тип, все свойства которого необязательны
- Pick: на основе переданного типа создаёт новый тип, имеющий только указанные ключи
- Omit: на основе переданного типа создаёт новый тип, имеющий все ключи, кроме указанных
- Record: на основе переданных ключей K и типа T создаёт объектный тип, в котором значения всех ключей имеют тип T
- Readonly: на основе переданного типа создаёт новый тип, все свойства которого доступны только для чтения, т.е. свойства объекта с получившимся типом нельзя будет изменять
